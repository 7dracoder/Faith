# Faith development

Faith is a blind-first iPhone app: hold anywhere and speak. Object requests go to the object finder (ARKit, spatial audio, AirPods head tracking); ticket requests go to an ElevenLabs voice agent whose tools run in the app against the Faith backend. There is no web client.

- Every spoken or audio state also has visible text and a VoiceOver label or action.
- Motion must never confirm or purchase. A practice booking or a saved live trip happens only by a 1.5 s hold on the choice screen or by the user's own spoken yes after the offer (checked in the app, never trusted from the agent alone). A double tap rejects it.
- Preserve object remembrance alongside ticketing. Camera/world coordinates must never cross AR session generations: guide only to positions measured in the current AR session, and clear targets when tracking is reset, interrupted, backgrounded, or the object area is left. Remembered object names and places persist until the user says “forget what you’ve seen”. Never invent metric distances or use fixed-depth fallback points for guidance.
- Object guidance is experimental, not obstacle detection or a safe route. Require user confirmation of found objects. Faith only sends pictures after the user asks, plus object-memory snapshots, which are announced once on first launch and can be turned off by voice; never capture on the booking screen or in the background. Memory pictures stay on the phone; the backend must never store or log images, and SurrealDB object memory holds only labels, places, times, and AR positions keyed by a hashed session. No camera/spatial telemetry.
- Preference memory holds only home city, step-free, audio description, companion seat, and usual party size, saved only when the user asks or agrees, keyed by a hash of the session. Never store objects, frames, or location there (object memory has its own record). Real-time and accessibility lookups are read-only and never bookable.
- Faith cannot pay or issue tickets. Live options come from read-only Anchor tasks on fixed provider hosts; choosing one only saves the trip and the provider link (SurrealDB `trip`, hashed session) and must never be described as booked or paid. Only option IDs from the session's own latest live search can be saved. The practice inventory is fictional: keep its demo and non-admission notices, and use it only when live search fails, saying so.
- Server-generated quotes own prices and expire. Confirmation must require explicit acknowledgement and remain idempotent.
- Test session ownership, duplicate confirmation, cancellation, pricing, expiry, and every ticket category when changing booking behavior.
- Never commit environment files, AWS tokens, provider keys, local databases, or generated Xcode projects. Never embed service secrets in clients.
- Do not send raw text, images, object labels, motion, audio, access preferences, session tokens, or identity to traces. Optional integrations must have honest disabled/failure states.
- Run backend tests and local synthetic evaluations. Build and test iOS when Xcode is available; report unavailable checks accurately.
